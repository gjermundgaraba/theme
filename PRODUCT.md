# Product

## Register

product

## Users

This is primarily for the owner of the theme system: a developer iterating quickly on a personal color environment across terminal, shell, editor, writing, and Neovim targets. The user is usually in a focused configuration workflow, comparing palettes, checking contrast, previewing generated output, and building or linking targets locally.

## Product Purpose

Generate coherent dark and light themes from a shared OKLCH-driven palette model. The tool should make palette changes immediate, show the practical effect across supported targets, validate contrast clearly, and keep generated outputs trustworthy enough to install without manual edits.

Success means the user can explore hue choices, catch contrast issues, regenerate all targets, and keep multiple applications visually aligned with low friction.

## Brand Personality

Expressive, color-forward, playful, precise, and developer-native. The interface should feel like a personal color instrument rather than generic admin software, while still respecting the directness expected from a local development tool.

## Anti-references

- Generic SaaS dashboard chrome.
- Drab monochrome developer utility.
- Decorative UI that obscures color judgment or generated output.
- Control-panel sprawl that turns quick theme iteration into design-system maintenance.

## Design Principles

- Make color manipulation immediate: controls should react quickly and expose cause and effect without ceremony.
- Keep generated outputs trustworthy: previews, templates, and build actions must match what will be installed.
- Treat contrast as a first-class signal: accessibility checks should be visible, specific, and hard to miss.
- Prefer task-native controls over decoration: every visual choice should help palette exploration, previewing, or validation.
- Preserve a personal, opinionated feel: the tool can be playful and color-forward without drifting into generic product chrome.

## Accessibility & Inclusion

Target WCAG AA for relevant UI text and controls. Prioritize strong contrast checks, keyboard usability for interactive controls, visible focus states, and reduced-motion-safe interactions. Because the product generates themes, contrast validation is part of both accessibility and core product quality.
